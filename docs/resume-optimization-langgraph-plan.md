# 简历定向优化 LangGraph 改造规格

## 目标

简历定向优化以对话为主工作区。用户在同一会话中上传简历、输入 JD、补充项目资料、确认或追问建议，直至主动结束。本页不再使用通用参考 Agent 的天气、待办、搜索、计算器能力。

## 用户流程

1. 用户批量上传一份简历和零至多个项目资料，支持 PDF、DOCX、TXT、MD；上传区可展开、收起、删除文件，并显示处理状态。
2. 用户输入 JD 并一键选择系统已有模型配置。
3. 系统快速清洗简历，生成可定位的文本块、段落与页码信息。
4. 主控智能体启动 LangGraph：JD 分析师拆解要求；Hybrid RAG 在简历与项目资料中召回证据；简历修改师生成有证据支撑的 Diff；HR 分析师审查匹配与风险；主控智能体在对话中汇总。
5. 若存在缺口，对话中逐条展示可定位 Diff、替换文本和一键复制；用户可在对话中追问、确认或标记完成。
6. 若已符合 JD，对话中说明亮点，并标出对应简历位置与证据。

## LangGraph 编排

状态包含会话消息、简历块、JD 结构化要求、检索证据、Diff 建议、HR 结论、选中的模型配置和事件日志。

```text
主控智能体 -> JD 分析师 -> Hybrid RAG -> 简历修改师 -> HR 分析师 -> 主控智能体
```

主控智能体可根据 HR 结论返回简历修改师补充建议，或结束本轮。所有节点仅使用用户选中的模型配置；长任务通过 RQ 执行，API 以会话快照和事件流返回进度。

## 智能体提示词原则

- 主控智能体：明确当前阶段、组织节点输入输出、汇总可执行结果；不编造事实。
- JD 分析师：只从 JD 抽取职责、硬技能、经验、优先级与检索词。
- 简历修改师：仅根据原简历和检索证据生成 Diff；每项给出原文、替换文案、理由、目标块和证据 ID。
- HR 分析师：以初筛标准审查关键词、可信度、量化表达和匹配风险；认可的亮点也必须定位。

JD 是评估标准，不是候选人事实来源。简历和项目资料是唯一可写入建议的事实证据。

## Hybrid RAG

复用现有关键词/BM25、向量检索与重排能力。简历解析块和上传项目资料被纳入同一次检索范围；JD 分析结果作为检索 query。每个结果必须携带文件名、块 ID、原文、得分和位置。项目资料可由用户选择是否参与当轮检索。

## 前端

- 中央对话为主要交互，支持发送、追问、运行状态和最终总结。
- 上传区和项目资料区可折叠，支持批量上传和删除。
- 模型配置选择器列出已有配置。
- 简历预览采用文档阅读器式的页/段落定位体验；点击对话中的 Diff 或亮点会定位并高亮原文。
- Diff 项显示原文与替换文案，提供复制按钮、接受/忽略状态；这些操作不得替代对话确认。

## 验收

- 四个 LangGraph 角色、提示词、状态图和事件可被单元测试验证。
- 批量 PDF/DOCX/TXT/MD 上传、删除、折叠和项目资料 RAG 范围可用。
- Hybrid RAG 使用关键词/BM25、向量检索和重排，返回可引用证据。
- 对话能够展示缺口 Diff 或匹配亮点，并可定位、复制。
- 前端构建和相关后端测试通过；旧通用参考 Agent 页面与路由不再是该功能的调用链。
